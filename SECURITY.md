# Security Policy

## Supported Versions

The following versions of Vatuta are currently being supported with security updates.

| Version | Supported          | Description                                |
| ------- | ------------------ | ------------------------------------------ |
| Latest  | :white_check_mark: | The most recent stable release             |
| `main`  | :white_check_mark: | The active development branch (pre-release)|
| Older   | :x:                | Older releases are not currently supported |

## Reporting a Vulnerability

We take the security of Vatuta seriously. If you believe you have found a security vulnerability
in this project, please report it to us privately.

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

Instead, please report them via **GitHub Private Vulnerability Reporting**:

1. On GitHub, navigate to the main page of the repository.
2. Under the repository name, click the **Security** (or **Security and quality**) tab.
3. Click **Report a vulnerability** to open the advisory form.
4. Fill in the advisory details form.
   > **Tip:** We recommend providing as much information as possible. You can adopt the template
   > used by the GitHub Security Lab, available at
   > [github/securitylab/docs/report-template.md][sec-template].
5. At the bottom of the form, click **Submit report**.

### What to expect

- We will acknowledge receipt of your vulnerability report within **7 days**.
- We will send you regular updates about our progress in investigating and fixing the issue.
- If the vulnerability is confirmed, we will coordinate with you to publish a patch and a security
  advisory. We will also credit you for the discovery upon public disclosure, unless you prefer
  to remain anonymous.

We ask that you follow coordinated disclosure practices and do not disclose the vulnerability
publicly until a patch has been released.

[sec-template]: https://github.com/github/securitylab/blob/main/docs/report-template.md
